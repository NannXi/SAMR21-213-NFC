# EPD1 v1 协议

## 传输和存储

MCU 使用 PA16 SDA、PA17 SCL 软件 I²C，地址 0x55。I²C SRAM 块 F8..FB，共 64 字节。会话寄存器 FE:2=01，FE:0 的掩码 43 写 03（镜像开、直通关、方向位 1），RF 页 04..13h 映射 SRAM。只改会话寄存器，不改 EEPROM 配置。

NFC EEPROM 的 0..55 块现场备份见 `nfc_eeprom_before.bin`。镜像在 VCC/POR 后失效，固件启动配置；RF 上电时是否会影响该批次镜像需真机确认。此版不是固定 F0..FFh SRAM pass-through 协议。

Android `NfcA`：READ 30h + 页号，返回 16 字节；WRITE A2h + 页号 + 4 字节，ACK 低四位 Ah。读四组 16 字节组成邮箱。写时先清第一页，再写后十五页，最后提交第一页。MCU 回应同样先清第一块、写后三块、最后写第一块。CRC32 拒绝并发造成的不完整帧；magic 顺序不构成硬件原子事务。

每包四次交换重试，每次 NFC 命令处理暂忙 / NAK 重试。设备仅保存上一个成功请求以便同包重传。SEQ 与 offset 严格递增。30 秒接收超时后可从 BEGIN 重传；没有断点续传。

## 帧布局（64 字节，所有整数小端）

| 偏移 | 长度 | 请求 / 响应 |
|---:|---:|---|
| 0 | 4 | EPD1 / EPA1 |
| 4 | 1 | 版本 1 |
| 5 | 1 | 操作码 / 操作码 OR 80h |
| 6 | 2 | seq |
| 8 | 4 | 随机非零 transfer_id |
| 12 | 2 | 图像 offset / 已收到字节数 |
| 14 | 1 | payload 长度，最大 44 / 响应 24 |
| 15 | 1 | 0 / 错误码 |
| 16 | 44 | payload / 元信息（余字节填 0） |
| 60 | 4 | 前 60 字节 CRC32 ISO-HDLC，初始与末尾 XOR FFFFFFFFh，多项式 EDB88320h |

操作码：1 BEGIN、2 DATA、3 COMMIT、4 STATUS、5 ABORT。

BEGIN seq=0、offset=0、len=11：payload 为 u16 宽 212、u16 高 104、u32 整图 CRC32、u16 长 5512、u8 格式 1。DATA seq 从 1 开始，payload 最多 44 字节。COMMIT seq 紧接末包，offset=5512、len=0；固件收齐后比对整图 CRC，才复制到显示帧缓冲。先发布 COMMIT ACK，再阻塞约 15 秒刷新，之后发布 DONE。ABORT 不能停止已开始的物理刷新。

响应 payload：16=状态（0 idle / 1 receiving / 2 refreshing / 3 done / 4 failed）、17=设备种类 1、18=u16 宽、20=u16 高、22=u16 长、24=u32 整图 CRC、28=u32 BWR1 设备签名 31525742h、32..38=UID 七字节。启动回复 op/seq/id=0。手机先核对有效响应、签名、尺寸、长度和实际 NFC UID，再进行写操作；这是设备匹配，不是密码认证或加密。

错误码：2 顺序/偏移不符、3 参数不支持、4 状态忙、5 会话不符、6 整图 CRC 不符、7 接收超时、8 刷新失败。包 CRC 错误静默丢弃，等待重试。

## 图像格式

横向 212×104，控制器原生 104×212。5512 字节=黑白平面 2756 + 红平面 2756。每个控制器行 13 字节，高位像素在前。

对横向 `(x,y)`：`index=(211-x)*13+y/8`，位掩码 `0x80>>(y%8)`。

| 色彩 | 平面 0 | 平面 1 |
|---|---:|---:|
| 白 | 1 | 1 |
| 黑 | 0 | 1 |
| 红 | 0 | 0 |

画布输出量化三色，不传灰度。整图在 RAM 暂存，收齐前保留旧画面；掉电后不会保存上传图像，上电显示内置示例。
