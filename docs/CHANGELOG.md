# 更新记录

## v0.1.1（2026-10-21，实验预发布）

- 用户实测 v0.1.0 识别到 NFC 标签，但固件握手或 transceive 失败，电池供电也复现。
- 板端捕获 GPIO 软件 I²C 高频轮询中的 HardFault；改为原板引脚 SERCOM1 硬件 I²C（约100 kHz）。关闭主循环睡眠/NVM 自动睡眠与缓存用于稳定性诊断，尚未实现低功耗。
- 50 ms 空闲轮询，先看一个 SRAM 块，有请求再读剩余块；为 RF 留出空闲时间。镜像每500 ms检查，丢失则重新初始化，初始化失败每秒重试。
- Android 身份握手最长等待6秒；日志包含手机型号、Tag UID、READ原始响应、失败命令；失败弹窗可“复制诊断”，不需 root/Shizuku。
- 错误文案不再把 TagLost 简单归因于用户移动手机。APK versionCode=2，同开发密钥签名，可覆盖原版。
- 已通过 Java 图像/协议测试、APK v2/v3签名验证、实板 SERCOM1 SRAM整图接收/重复包/CRC/刷新/DONE/EEPROM比较；手机端到端传图仍待重测。

## v0.1.0（2026-10-21）

初始212×104编辑画布、选图/拖动裁切/缩放/旋转、亮度/对比度/抖动、三色量化与EPD1协议。手机上传未成功，长时间运行出现板端异常；保留历史版本，请使用v0.1.1诊断版。

## v0.1.2 邮箱迁移（2026-10-21）

手机日志已读取完整 EPA1、UID 和尺寸，但第一条 A2 04 写命令失败。旧邮箱选址有误：静态锁 F0 FF，RF 04h..0Fh 只读；动态锁 FF 00 00，RF 10h..8Fh 也被锁定。动态锁在 I2C block38h 字节8..10，不在块首。

新邮箱 RF 90h..9Fh，I2C镜像块24h，目标动态锁byte1 bit0清零。保持全部锁位、用户EEPROM和持久配置不变。Android先只读锁位、校验UID/签名/邮箱版本再写。固件和APK须同时升级至0.1.2。

RF场存在时MCU只读会话寄存器；手机每读完邮箱后静默90ms，MCU在最后块读取事件20ms后访问SRAM。LAST_NDEF_BLOCK=27h，手机presence-check间隔1秒。响应字节39=90h，40=布局修订2。写完一帧后额外READ9Ch发出交接事件。无RF场时50ms轮询，镜像配置每500ms检查恢复。

板端SWD经真实I2C到SRAM整图5512字节、重复包、CRC、刷新和DONE通过。手机0.1.2端到端仍待验证；不能把电脑测试当成手机上传成功。0.1.1的3004失败仍可能涉及仲裁，不能仅凭异常判定手机移开。
